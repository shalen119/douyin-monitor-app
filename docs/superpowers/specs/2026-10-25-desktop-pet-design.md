# 抖音监测桌宠设计稿

日期：2026-10-25。状态：用户已确认开始制作。

## 目的与边界

用用户确认的蓝色系 Q 版像素角色，给现有 Windows 本地抖音监测台增加可见、可交互的入口。解决启动时必须保持 CMD 窗口打开的问题；让用户在桌面看到采集进度、命中和异常，并偶尔收到发布作品及账号日常运营的提醒。

桌宠是监测台的伴随程序。现有网页、Node.js 监测服务、数据目录、抖音专用 Edge 登录会话和飞书提醒继续承担原有职责。桌宠不执行抖音账号操作，不替代用户登录，不自动发布作品，也不改变现有采集口径。后期修改统计、设置或视频管理页面，原则上不需要修改桌宠。

## 已确认的体验

- Windows 上手动双击桌宠入口启动；不开机自启。桌宠播放开场动画时启动或连接监测服务，确认服务状态后再进入可操作的工作状态。服务已运行时复用，不启动第二份。监测服务在后台运行，不要求保留 CMD 窗口。
- 每次手动启动桌宠，都先播放“在小床上睡醒、揉眼、爬起、站稳”的像素开场动画，再进入当前真实工作状态。小床是开场道具，动画结束后收起，不长期占用桌面。服务启动可与动画并行；动画不伪称服务已就绪，若启动失败，结束后进入异常提示。
- 桌宠始终置顶，可拖动；默认在屏幕右下角。双击角色打开现有监测台。关闭角色窗口等于隐藏到系统托盘，采集继续；只有托盘菜单中的“退出监测”才停止桌宠管理的服务。托盘菜单还提供显示桌宠、打开监测台、暂停/恢复监测、设置和退出。关闭网页不停止采集。
- 抖音登录与采集使用的专用 Edge 仍按现有逻辑打开。桌宠不伪装成抖音登录窗口。电脑睡眠或断网期间无法采集；恢复后显示实际状态。
- 角色以已确认的[四视图像素设定图](assets/blue-pet-turnaround.png)为外观基准：蓝色短发、向上卷起的发梢、星形发夹、蓝白连帽外套、深色内搭和靴子。制作透明背景、像素边缘清晰、比例一致的逐帧素材。四视图设定不是可直接播放的动画帧。

## 状态、动画与气泡

桌宠至少有启动开场、待机、正在采集、发现命中、采集异常五类状态。桌宠读取服务真实状态和事件，不用随机动作冒充采集进度。当前 `/api/state` 只有粗粒度运行信息，实施时需补充适合桌宠的当前采集任务、同时正在检查的视频数量与事件信息；传输方式由实施计划决定。这个数量指此刻实际并发检查中的视频数，不是已添加或未暂停的视频总数；检查结束后及时清零并切回待机，不显示过时数字。状态事件应包含可用于打开对应视频或命中记录的标识，不向桌宠发送飞书 Webhook、登录 Cookie 等密钥。

| 状态 | 动画方向 | 文字气泡例句 |
| --- | --- | --- |
| 启动开场 | 在蓝白色小床上醒来、揉眼、爬起、站稳；仅每次手动启动播放一次 | “醒啦，今天也一起盯着作品吧。” |
| 待机 | 眨眼、呼吸；偶尔伸懒腰、整理发夹、翻小本子、看小屏幕、抱杯休息 | “我在这儿守着呢。” |
| 正在采集 | 查看小屏幕，胸前状态灯闪动；显示此刻正在检查的视频数，可显示当前作品的短标题 | “正盯着两条呢，有我在！”“三条一起看，也难不倒我～” |
| 发现命中 | 轻跳一次、落地、星形发夹闪亮；气泡指明作品，点击直达对应命中记录 | “找到一条需要你看看！” |
| 采集异常 | 歪头、小屏幕变暗；气泡指明作品和简短原因，点击打开运行状态 | “这条视频暂时没读到，我再试试。” |

逐帧动画先产出循环预览供用户确认，再接入程序。像素角色需保持发型、服装、轮廓和脚底基线一致，避免每帧变脸。动画频率、帧数和技术格式由实施者根据小尺寸显示效果决定。每种状态配多条自然、可爱的短句；避免连续重复同一句。采集气泡使用带实时数量的多样句式，按中文习惯写“一条、两条、三条”等；数量改变时更新内容，不凭固定文案猜测数量。“别催我啦”用于较长采集，不在每次检查时出现。所有提示只用文字气泡，无语音。

“命中小跳”用于新评论命中词库，以及点赞量或平台评论总数达到设定阈值的提醒。首次历史补采和手动词库重新匹配只用较轻提示，不触发小跳。相同提醒事件只播放一次，桌宠重新连接服务时不重复表演旧提醒。

命中和异常高于采集，采集高于待机动作与日常提醒。一次事件只触发一次显著动画；短时间连续事件可合并提示，避免角色不停跳动。气泡可点击或自行消失；错误状态在角色或托盘中保持可查看，不靠短暂气泡作为唯一告知渠道。默认气泡只显示作品名称、命中类别或简短原因，不直接在桌面展示完整评论文本；详情由现有监测台承载。

## 偶发提醒

待机时偶尔随机出现一句“记得发作品”或“记得养号/查看账号日常”的提示，伴随翻本子或举便签动作，不打开待办清单，也不自动操作账号。提醒属于低优先级，采集、命中、异常发生时不显示或延后。

设置可启停该提醒，调整允许时段和每日次数。我的默认值：本地时间 10:00–21:00，每天随机 1–2 次，两次至少间隔 3 小时；同一语句避免短期重复。程序关闭期间错过的提醒不补发。提示语词库可逐步扩充，初版允许用户关闭提醒，不要求用户自己编辑词库。设置入口放在桌宠/托盘的专属设置界面，避免强行改动监测台主布局。

## 启停与恢复

- 启动时检查本机服务是否属于当前监测台，再决定连接或启动；避免仅凭端口开放就误认其他程序。服务启动失败时桌宠显示明确错误和重试入口，不假装正在监测。
- 隐藏到托盘、关闭网页或关闭抖音采集窗口不等于退出监测。关闭采集窗口后继续采用现有重开逻辑；登录失效时提示用户重新登录。
- 用户选择“退出监测”时停止由桌宠启动的本机服务并退出桌宠；原有未通过桌宠启动的服务不应被误杀。异常崩溃或系统重启后，下次手动打开可读取原有 `data` 和登录资料继续工作。
- 托盘“暂停监测”作为全局调度暂停：不修改单条视频原有的暂停标记，也不删除排队记录；该全局状态保存到下次启动。恢复后按现有补采规则继续检查，不把停机期间的评论冒充为当期新增。这是设计者的默认决定，用户可在确认稿时调整。
- 在托盘与桌宠都能看见“运行中、暂停、错误”这类真实状态。具体实现须避免桌宠和服务重复实例、残留进程及相同数据目录被两个实例同时写入。

## 制作与验收

先依据设定图制作睡醒开场、待机、采集、命中小跳、异常的透明逐帧素材和预览，确认角色一致性与动作节奏；然后制作 Windows 置顶透明桌宠窗口与托盘；最后接入服务生命周期、状态事件、深链和提醒设置。桌宠与网页保持独立，协议接口版本和错误处理在实施计划中确定。

验收时需验证：每次手动启动只播放一次睡醒开场；双击启动无常驻 CMD；服务只启动一次；桌宠隐藏后采集继续；退出监测能干净结束桌宠管理的服务；采集气泡显示真实的同时检查数并随开始、结束更新；评论词命中和数值阈值触发小跳，历史补采与重匹配只轻提示；命中与异常对应正确视频；随机提醒受时段和频率限制；无声、无自动账号操作；现有监测网页、飞书推送、登录和数据持久化继续可用。更新安装包时包含桌宠与其素材，但不打包用户的 `data`、登录 Cookie 或飞书密钥。

## 留给实施者的决定

Windows 桌宠壳与动画播放技术、帧数和播放速度、气泡停留秒数、窗口默认像素尺寸、服务事件传输机制、进程归属与打包工具，在实施计划中选择；选择应优先复用现有 Node.js 监测服务、保证清晰像素外观与后期独立维护。
